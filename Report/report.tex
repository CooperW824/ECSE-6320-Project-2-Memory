\section{Introduction}
% Context, motivation, system under test, and objective of this experiment.

% =====================================================

The goal of this project is to analyze how the memory hierarchy impacts performance of the simple computations as the
working set size, data stride \& access pattern, read-write ratio, access intensity, and page size changes.

To do this I will use 4 different computational kernels:

\begin{enumerate}
	\item Array Reduction, Summing all values of an array: 100\% read.
	\item Memset, setting all values in an array to one value: 100\% write.
	\item Vector-Vector Multiply, element-wise multiplication of two vectors: 66\% read / 33\% write.
	\item Scalar-Vector Multiply, element-wise multiplication with a scalar: 50 \% read / 50\% write.
\end{enumerate}

To change the other experimental variables, I have a main kernel runner that can control the working set size, the
stride of the data, run with random access patterns, number of threads accessing the data. To be able to control the
page size, I will be running this code in a Linux VM where I can set the memory page size to either 4KiB or 2MiB.

\section{Pre-Experiment Hypotheses}

\begin{hypothesisbox}
	\textbf{Hypothesis:} \\
	% State the falsifiable prediction before running anything.

	Huge pages will help with reducing the number of TLB misses. However, this will only help when the working set size is
	large, for small working sets that fit into a small number of pages, the larger page sizes will have little if any
	impact on performance.

	\textbf{Reasoning:} \\
	% Why do you expect this outcome? Reference architecture, prior results, theory.
	For larger working set sizes, with small pages of 4KiB, the data will span potentially thousands of pages creating a
	large number of TLB misses, each TLB miss causing a page fault and requiring a ring level switch to fetch a page
	address. This ring level switch will become a large part of the the time spent during computation.

	By switching to large pages, the larger working set data can fit into a fewer number of pages, reducing the number of
	TLB cache misses and therefore reducing the time spent handling page faults, improving performance.

	\textbf{Predicted quantitative outcome:} \\
	\begin{center}
		\captionof{table}{Huge Page Speedup}
		\label{tab:hypothesis-huge-pages}
		\begin{tabular}{lc}
			\toprule
			\textbf{Working Set Size} & \textbf{Huge Page Speedup} \\
			\midrule
			1,024                     & $1x$                       \\
			16,384                    & $1.05x$                    \\
			65,536                    & $1.1x$                     \\
			1,048,576                 & $1.5x$                     \\
			16,777,216                & $2x$                       \\
			268,435,456               & $2.7x$                     \\
			\bottomrule
		\end{tabular}
	\end{center}
\end{hypothesisbox}

\begin{hypothesisbox}
	\textbf{Hypothesis:} \\
	% State the falsifiable prediction before running anything.

	As the access pattern demonstrates lower spatial locality with larger strides and random access patterns, the
	computational performance will drop significantly as there will be more cache misses.

	\textbf{Reasoning:} \\
	% Why do you expect this outcome? Reference architecture, prior results, theory.

	The more sporadic access patterns will have to fetch from main memory more frequently, this will result in more
	pipeline stalls as data is no longer resident in cache. With the smaller strides, more useful data will be in each
	cache line and therefore more data will be able to be prefetched.

	\textbf{Predicted quantitative outcome:} \\
	% e.g., "Expect L2 miss rate to decrease by \SI{15}{\percent} \pm \SI{3}{\percent}"
	\begin{center}

			8                               & $0.87x$           \\
